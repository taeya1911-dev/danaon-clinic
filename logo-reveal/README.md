# 로고 타이프라이터 리빌 (4초)

검정 배경에 워드마크가 터미널처럼 한 글자씩 타이핑되는 4초짜리 고정 숏.

**지금 상태: 움직임은 완성됐고 워드마크는 자리표시자다.** 원본 로고 이미지를 받지
못해서 `config.json`의 텍스트가 `PLACEHOLDER`로 들어가 있다. 아래 "로고 넣기"만
하면 최종본이 나온다.

## 왜 영상 생성 AI가 아니라 코드인가

브리프의 핵심 요구가 "철자·자형·자간·굵기·색을 원본 그대로"인데, 생성 모델은
바로 그걸 보장하지 못한다. 글자를 흘려 쓰거나 한 글자를 빠뜨려도 결과물로는
그럴듯해 보인다. 여기서는 실제 폰트 파일로 글자를 그리므로 자형이 원본과
같다는 게 정의상 보장된다. 타이핑 박자도 프레임 단위로 정확하다.

## 쓰는 법

```bash
node render.mjs      # out/logo-reveal.mp4 생성
node verify.mjs      # 결과물이 브리프대로인지 검사
```

옵션: `--gif`(GIF도 생성), `--keep-frames`(PNG 시퀀스 보존),
`--config`/`--spec`/`--out`으로 경로 지정.

## 로고 넣기

`config.json`의 `wordmark`만 고치면 된다.

```jsonc
"wordmark": {
  "segments": [                              // 로고가 두 가지 색이면 색깔별로 나눈다
    { "text": "danaon", "color": "#FFFFFF" }
  ],
  "fontFamily": "Pretendard",                // 폰트 파일 안의 패밀리 이름
  "fontFile": "fonts/Pretendard-Bold.otf",   // 이 파일 기준 상대 경로
  "fontWeight": 700,
  "letterSpacingEm": 0.02,                   // 원본 로고의 자간
  "targetWidthRatio": 0.62                   // 워드마크가 화면 폭의 몇 %를 차지할지
}
```

`fontFile`을 비워두면 시스템 폰트로 그린다. 지정한 폰트를 못 찾으면 렌더러가
경고를 띄운다 — **이 경고를 무시하면 자형이 원본과 달라진다.** 브라우저는 없는
폰트를 조용히 대체 폰트로 바꿔 그리기 때문에, 경고가 유일한 신호다.

한글 워드마크라면 이 컨테이너에는 한글 폰트가 없으므로 `fontFile`이 필수다.

## 타임라인

`spec.json`에 있다. 브리프의 4구간을 그대로 옮겼다.

| 시간 | 화면 |
|---|---|
| 0.0-0.6 | 검정 화면 + 워드마크 시작 위치에 흰 캐럿, 일정하게 깜빡임 |
| 0.6-2.8 | 워드마크가 왼→오 한 글자씩. 캐럿이 다음 글자 자리로 이동 |
| 2.8-3.4 | 완성된 워드마크 끝에서 캐럿이 두 번 깜빡이고 사라짐 |
| 3.4-4.0 | 워드마크만 정중앙에 정지 |

## 설계에서 정한 것 (다시 논의하지 말 것)

- **워드마크는 왼쪽 끝이 고정이다.** 완성됐을 때 정중앙에 오는 위치를 먼저 계산하고,
  그 왼쪽 끝에 글자를 쌓는다. 매 프레임 가운데 정렬을 다시 하면 이미 찍힌 글자가
  왼쪽으로 밀리는데, 그게 브리프가 금지한 slide다. `verify.mjs`가 이걸 검사한다.

- **가운데 정렬은 advance box가 아니라 잉크 기준이다.** advance box에는 첫 글자의
  왼쪽 사이드베어링과 마지막 글자의 오른쪽 사이드베어링이 들어 있고 둘은 보통
  다르다. 그대로 맞추면 눈에는 한쪽으로 치우쳐 보인다. 세로도 마찬가지 이유로
  em box가 아니라 잉크의 위아래 끝으로 맞춘다.

- **타이핑 중에는 캐럿이 깜빡이지 않는다.** 실제 터미널은 키를 누를 때마다 깜빡임
  위상이 리셋돼서 입력 중에는 캐럿이 계속 켜져 있다. 브리프의 "정확히 터미널에서
  타이핑되는 것처럼"을 따른 결과다. 깜빡이게 하려면 `spec.json`의
  `typing.solidWhileTyping`을 `false`로. (글자당 간격이 짧아서 켜면 깜빡이 아니라
  스트로브로 보인다.)

- **글자 위치는 prefix 단위로 잰다.** 글자를 하나씩 재서 더하면 커닝이 무시되고
  완성본의 자간이 원본 로고와 달라진다.

- **화면 녹화가 아니라 프레임을 하나씩 찍는다.** 녹화는 프레임이 밀리거나 중복돼서
  "일정하고 기계적인" 박자가 흔들린다. `drawAt(t)`를 `t = 프레임/fps`로 직접
  호출하면 박자가 스펙과 정확히 일치한다.

## 검사기

`verify.mjs`는 reveal.html의 로직이 아니라 **인코딩된 mp4**를 디코딩해서 검사한다.
폰트나 자간을 바꿨을 때 조용히 깨지는 것들을 잡는 게 목적이다.

12개 항목: 길이 4.0초 / 배경 순수 검정 / 0초에 캐럿만 / 캐럿 깜빡임 /
타이핑 좌→우 단조 증가 / 글자 밀림 없음 / 2.8초 완성 / 마무리 깜빡임 2회 후 소멸 /
홀드 구간 완전 정지 / 최종 가운데 정렬 / 좌우 여백 / 상하 여백.

검사기 자체는 일부러 깨뜨려서 확인했다 — 배경색을 남색으로, 워드마크를 화면 95%로,
깜빡임을 4회로, drawAt에서 매 프레임 재정렬하도록 각각 개악했을 때 해당 항목만
정확히 실패했다.
