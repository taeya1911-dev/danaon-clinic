# 캡컷 영상 자동 편집

영상 파일 하나를 넣으면 무음을 정리하고 자막을 얹은 캡컷 프로젝트가 나오는 도구를, 추측 없이 단계적으로 만든다.

## 이 스킬이 존재하는 이유

캡컷 자동화가 실패하는 방식은 거의 항상 똑같다. 프로젝트 파일 구조를 **인터넷에서 본 대로 가정하고** 코드를 먼저 쓰는 것이다. 캡컷은 버전마다 스키마가 바뀌고 지역판마다 경로가 다르기 때문에, 가정으로 쓴 코드는 "파일은 생성됐는데 캡컷에서 안 열림"으로 끝난다. 그때는 이미 코드가 수백 줄이라 어디서부터 틀렸는지 찾기가 비싸다.

그래서 이 워크플로는 **사용자의 실제 파일에서 정답을 복사해오는 단계를 코드 작성보다 앞에 둔다.** 순서를 지키는 것 자체가 이 스킬의 핵심이다.

## 절대 원칙

**1. 확인한 것만 말한다.** 파일 경로, 스키마 필드명, 시간 단위는 실제로 열어서 본 것만 사실로 취급한다. 확인 못 했으면 "확인 못 함"이라고 명시한다. 여기서 그럴듯하게 지어내면 뒤 단계 전부가 조용히 썩는다.

**2. 원본은 읽기 전용이다.** 사용자의 영상 원본과 기존 캡컷 프로젝트는 절대 수정·삭제하지 않는다. 새 프로젝트는 항상 새 폴더에 만들고, 기존 폴더 이름을 재사용하지 않는다.

**3. 캡컷이 실행 중이면 프로젝트 파일을 쓰지 않는다.** 캡컷은 종료 시점에 메모리 내용을 파일에 덮어쓴다. 켜둔 채로 파일을 고치면 작업이 통째로 날아간다. 파일 쓰기 전에 프로세스를 확인하고, 실행 중이면 사용자에게 먼저 알린다.

**4. 각 단계는 통과 기준을 넘겨야 다음으로 간다.** 기준을 못 넘으면 다음 단계로 진행하지 말고 사용자에게 상황을 보고한다. 특히 1~2단계를 건너뛰고 5단계로 점프하고 싶은 유혹이 크지만, 그렇게 하면 반드시 돌아오게 된다.

## 진행 상태 관리

작업이 여러 세션에 걸치므로 진행 상황을 `.capcut-auto/state.json`에 기록한다. 스킬을 시작할 때 이 파일이 있으면 먼저 읽고, 이미 통과한 단계는 다시 하지 않는다.

```json
{
  "capcut_version": "확인된 버전",
  "project_dir": "확인된 프로젝트 폴더 경로",
  "timeline_file": "타임라인 파일명",
  "time_unit": "microseconds",
  "phases_passed": [1, 2, 3],
  "notes": "단계별로 알아낸 것 중 기억할 만한 것"
}
```

## 단계

각 단계의 사용자용 프롬프트 전문과 세부 지시는 `references/phases.md`에 있다. 해당 단계를 시작할 때 그 부분을 읽는다.

### 1단계 — 포맷 탐색

캡컷 버전, 프로젝트 저장 경로, 타임라인 파일, 시간 단위를 사용자 컴퓨터에서 직접 확인한다. 경로 후보와 확인 방법은 `references/capcut-format.md` 참고 — 단 그 문서의 경로는 **검증 대상이지 정답이 아니다.**

시간 단위는 추측하지 말고 실측한다. 타임라인의 마지막 세그먼트 종료값을 영상 실제 길이와 나눠보면 단위가 바로 드러난다.

> **통과 기준:** 프로젝트 폴더의 실제 파일 목록이 명령 출력으로 나왔고, 타임라인 파일을 열어 사람이 읽을 수 있음을 보였다.
>
> **여기서 멈춰야 하는 경우:** 타임라인 파일이 암호화·압축돼 있어 읽히지 않으면 자동 생성은 불가능하다. 진행하지 말고 대안(자막은 SRT로 내보내 캡컷에서 가져오기, 컷 목록은 EDL로 내보내기)을 제안한다.

### 2단계 — 자막 구조 추출 (diff 기법)

자막 하나에 관여하는 필드는 파일 전체에 흩어져 있어서, 통째로 읽으면 무엇이 자막용인지 특정할 수 없다. **자막 없는 프로젝트와 자막 하나만 있는 프로젝트를 diff 뜨면 바뀐 부분이 곧 정답이다.**

사용자에게 캡컷에서 A(자막 없음)/B(자막 1개) 두 상태를 만들어 저장하게 하고, 두 폴더를 diff 한다. 절차와 주의사항은 `references/capcut-format.md`.

추출 결과는 `templates/subtitle_block.json`으로 저장하되 가변값을 `{{TEXT}}` `{{START_US}}` `{{END_US}}` 같은 placeholder로 바꾼다.

> **통과 기준:** 그 템플릿으로 자막 2개짜리 프로젝트를 조립했더니 캡컷에서 실제로 열리고 자막이 화면에 보인다.
>
> **흔한 실패:** 세그먼트와 소재(material)를 잇는 id 참조를 빼먹으면 파일은 열리는데 자막이 안 보인다. 안 보이면 이걸 먼저 의심한다.

### 3단계 — 사용자 기본값 조사

기존 캡컷 프로젝트를 전부 스캔해 자막 크기·색·위치·글자수·노출시간을 수집한다.

평균이 아니라 **중앙값**을 쓴다(자막 하나 크게 넣은 썸네일용 텍스트 같은 이상치가 평균을 망친다). 폰트 크기는 반드시 **캔버스 높이 대비 비율**로 정규화한다 — 1080p 프로젝트와 4K 프로젝트의 크기 숫자를 그대로 비교하면 무의미하다. 가로(16:9)와 세로(9:16)는 따로 집계한다.

표본이 3개 미만이면 "데이터 부족"이라고 말하고 기본값을 단정하지 않는다.

> **통과 기준:** `config/defaults.yaml`이 생겼고 각 값에 "표본 N개, 중앙값" 근거가 주석으로 붙어 있다. 뼈대는 `assets/config-template.yaml`.

### 4단계 — 편집 습관 역분석

사용자가 같은 원본으로 직접 편집해 올린 결과물이 있으면, 원본과 비교해 컷 편집 습관을 수치화한다. **이 단계의 출력이 5단계의 기본 파라미터가 된다** — 측정만 하고 안 쓰면 의미가 없다.

두 영상 정렬은 오디오 상호상관(cross-correlation)으로 한다. 눈대중이나 자막 대조로 때우면 오차가 누적돼 통계가 무너진다. 매칭 실패 구간은 숨기지 말고 "정렬 실패"로 보고하고 통계에서 제외한다.

가장 중요한 산출물은 **"무음인데도 살린 구간"의 목록과 그 이유**다. 여기서 보호 규칙(8단계)의 임계값이 나온다.

> **통과 기준:** 아래 4개가 실측치로 채워졌다 — 무음 판정 음량 임계(dB), 무음 최소 길이(초), 컷 앞뒤 여백(초), 삭제 금지 화면변화 임계.
>
> 편집본이 없으면 이 단계는 건너뛰되, config 기본값이 측정치가 아니라 추정치임을 사용자에게 명시한다.

### 5단계 — 생성기 구현

`make_project.py INPUT.mp4 --out "프로젝트명"` 형태의 CLI를 만든다.

- 기본 동작은 `--dry-run`: 무엇을 자르고 자막을 몇 개 넣을지 계획만 출력하고 파일은 쓰지 않는다. 실제 생성은 `--write`를 명시해야 한다.
- 출력 폴더가 이미 있으면 덮어쓰지 않고 에러로 멈춘다.
- 하드코딩 금지. 모든 임계값은 `config/defaults.yaml`에서 읽고 CLI 인자로 덮어쓸 수 있게 한다.
- 중간 산출물(음성인식 결과, 컷 목록)을 JSON으로 남긴다. 검사와 디버깅이 여기에 의존한다.
- 실패를 조용히 넘기지 않는다. 종료 코드 1과 원인 출력.

무음 구간 판정은 직접 짜지 말고 `scripts/silence_plan.py`를 쓴다(아래 참고).

> **통과 기준:** 실제 영상으로 `--dry-run`이 돌았고 컷 개수·자막 개수가 상식적인 범위다.

### 6단계 — 검사기 (구현 직후 바로)

`verify_project.py "프로젝트폴더"`로 생성 결과를 검증한다. 검사 항목 8개와 판정 기준은 `references/verify-checklist.md`.

**만든 직후 반드시 할 것:** 정상 프로젝트를 복사해 8가지 방식으로 일부러 훼손하고, 검사기가 그 8개를 전부 잡아내는지 확인한다. 정상본은 통과해야 한다. 항상 통과하는 검사기는 없느니만 못하고, 이 확인 없이는 검사기가 작동하는지 알 방법이 없다.

> **통과 기준:** 훼손 샘플 8개 전부에서 실패 판정이 났고 정상본은 통과했다. 결과표를 사용자에게 보인다.

### 7단계 — 음성인식 캐시

같은 영상을 다시 돌릴 때 인식을 건너뛴다. 캐시 키는 **파일명이 아니라 내용 해시 + 모델명·버전 + 인식 파라미터**를 합쳐 만든다. 파일명 기준으로 하면 같은 이름으로 영상을 갈아끼웠을 때 옛 결과를 써서 원인 못 찾는 버그가 난다.

- 위치는 `.cache/transcripts/`, `.gitignore`에 추가한다.
- 히트/미스를 로그로 알린다. 캐시가 조용히 동작하면 디버깅 중에 사람을 미치게 만든다.
- `--no-cache`, `--clear-cache` 옵션을 둔다.
- 캐시 파일이 깨져 있으면 에러로 죽지 말고 무시하고 재실행한다.

> **통과 기준:** 2회차 실행 시간 단축이 실측으로 나왔고, 파일 내용을 바꾸면 미스가 나는 것을 확인했다.

### 8단계 — 컷과 자막 다듬기

**무음 처리** — 완전 삭제가 아니라 기본 0.5초까지만 줄인다. 컷 경계는 무음 구간 한가운데로 잡고 발화 앞뒤로 여백을 남긴다(칼같이 자르면 숨소리가 잘려 부자연스럽다). 결과 클립이 최소 길이 미만이면 앞 클립에 병합한다.

**보호 규칙(가장 중요)** — 오디오 음량만으로 판단하면 말없이 시연하는 구간이 통째로 날아간다. 무음이어도 화면 변화량이 크거나 사용자가 `--keep`으로 지정한 구간은 원본 길이를 유지한다. 판정 로그에 구간마다 "삭제 / 축소 / 보존"과 사유를 남겨 사용자가 오판을 잡을 수 있게 한다. 구현은 `scripts/silence_plan.py`가 담당한다.

**자막 줄바꿈** — 글자 수만 세서 자르면 조사가 다음 줄로 넘어가 읽기 불편해진다. 문장 끝 → 절 경계 → 어절 경계 순으로 나눈다. 규칙 상세는 `references/subtitle-rules.md`, 구현은 `scripts/split_subtitles.py`.

> **통과 기준:** 무음 판정 로그에 구간별 사유가 남았고, 무언 시연 구간이 "보존"으로 찍혔다. 자막 분할 전/후 목록을 나란히 보여 사용자가 확인했다.

### 9단계 — 사람 눈 검증

자동 검사는 파일 구조만 보지 화면은 못 본다. 성격이 다른 영상 3개(말이 이어지는 것 / 무언 시연이 있는 것 / 컷이 많은 짧은 것)를 처리하고, 사용자가 캡컷에서 직접 열어 확인할 체크리스트를 만든다.

사용자가 지적한 실패 항목은 **6단계 검사기의 자동 항목으로 승격시킨다.** 같은 실수를 두 번 겪지 않기 위한 장치다.

### 10단계 — 회귀 세트

짧은 샘플 영상 3~5개(10~30초)와 각각의 정답 스냅샷을 `tests/`에 두고, `run_tests.sh` 하나로 전부 돌린다. 이후 코드를 고칠 때마다 이걸 돌린 결과를 보고한다.

## 번들 스크립트

매번 새로 짤 필요 없는 부분은 미리 들어 있다. 다시 구현하지 말고 이걸 쓰거나 확장한다.

**`scripts/silence_plan.py`** — ffmpeg의 무음 감지와 장면 변화 감지 결과를 합쳐 구간별 "삭제/축소/보존" 계획을 JSON으로 만든다. 보호 규칙이 여기 들어 있다.

```bash
python scripts/silence_plan.py INPUT.mp4 --config config/defaults.yaml --out cut_plan.json
python scripts/silence_plan.py INPUT.mp4 --keep 00:01:23-00:01:45   # 구간 강제 보존
```

ffmpeg이 필요하다. 없으면 설치를 안내한다. `--from-json`으로 탐지 결과를 직접 넘길 수도 있어서, ffmpeg 호출부가 환경에 안 맞을 때 판정 로직만 떼어 쓸 수 있다.

두 스크립트 모두 `--self-test`를 갖고 있다. 파싱과 판정 규칙은 이 테스트로 검증돼 있지만 **ffmpeg 실제 호출 부분은 영상이 있어야 확인되므로, 처음 실제 영상에 돌릴 때 무음 감지 개수가 상식적인지 한 번 눈으로 확인한다.** 0개가 나오면 `silence_threshold_db`가 낮은 것이다.

**`scripts/split_subtitles.py`** — 한국어 자막을 문맥 경계에서 나눈다. 표준입력으로 자막 JSON을 받아 분할된 JSON을 낸다.

```bash
python scripts/split_subtitles.py --max-chars 20 --max-cps 9 < transcript.json > subtitles.json
python scripts/split_subtitles.py --self-test   # 규칙이 의도대로 도는지 확인
```

## 흔한 실패와 진단

| 증상 | 먼저 의심할 것 |
|---|---|
| 프로젝트가 캡컷에서 아예 안 열림 | 필수 파일 누락, JSON 문법 오류, 캡컷 버전과 스키마 불일치 (1단계로) |
| 열리는데 자막이 안 보임 | 소재↔세그먼트 id 참조 누락 (2단계로) |
| 자막은 뜨는데 타이밍이 밀림 | 시간 단위 오해(초/밀리초/마이크로초) 또는 컷 삭제 후 자막 시각 재계산 누락 |
| 자막 크기가 이상함 | 폰트 크기를 절대값으로 넣음 — 해상도 대비 비율로 환산 (3단계로) |
| 말하는 부분이 잘림 | 무음 임계가 너무 높거나 여백이 0 |
| 시연 구간이 날아감 | 보호 규칙 미적용 — `silence_plan.py`의 화면변화 임계 확인 (8단계) |
| 어제 되던 게 오늘 안 됨 | 캡컷 자동 업데이트로 스키마가 바뀜 — 1단계 재확인 |
