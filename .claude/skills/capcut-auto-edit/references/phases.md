# 단계별 프롬프트 전문

사용자가 직접 단계를 돌리고 싶어 하거나, 다른 도구/세션에서 이어서 작업할 때 그대로 복사해 쓸 수 있는 프롬프트 모음이다.
스킬이 워크플로를 직접 수행할 때는 SKILL.md의 단계 설명만으로 충분하며, 여기는 사용자에게 건네줄 용도다.

---

## 0. 공통 규칙 (한 번만, `CLAUDE.md`에 넣어두면 매번 안 써도 됨)

```
이 프로젝트 작업 시 항상 지킬 규칙:

[사실 확인]
- 파일 경로, 스키마 필드명, 버전 번호는 반드시 실제로 열어보고 확인한 것만 말해.
- 확인 못 한 건 "확인 못 함"이라고 명시해. 그럴듯한 추측을 사실처럼 쓰지 마.
- 캡컷은 버전마다 프로젝트 포맷이 바뀐다. 내 설치 버전을 먼저 확인하고,
  인터넷에서 본 구조와 다르면 내 파일 쪽을 정답으로 삼아.

[안전]
- 원본 영상 파일과 기존 캡컷 프로젝트는 절대 수정·삭제하지 마. 읽기 전용.
- 새 프로젝트는 항상 새 폴더에 만들어. 기존 폴더 이름 재사용 금지.
- 파괴적 동작(덮어쓰기, 삭제)은 실행 전에 나한테 물어봐.
- 캡컷을 켜둔 상태로 프로젝트 파일을 건드리면 앱이 덮어써서 날아간다.
  파일 쓰기 전에 캡컷이 실행 중인지 확인하고, 켜져 있으면 먼저 알려줘.

[작업 방식]
- 한 번에 한 단계만. 끝나면 검증 결과를 보여주고 멈춰.
- 코드를 만들면 반드시 실제로 실행해서 통과하는 걸 보여줘. "될 겁니다"는 안 됨.
- 개인정보(내 이름, 계정 ID, 파일 경로 속 사용자명)는 결과물에 남기지 말고
  <USER> 같은 placeholder로 치환해.
```

## 1. 탐색

```
캡컷 데스크톱이 프로젝트를 어디에 어떤 형식으로 저장하는지 내 컴퓨터에서 직접 확인해줘.

찾을 것:
1. 내 캡컷 버전
2. 프로젝트가 저장되는 실제 폴더 경로
3. 프로젝트 폴더 하나 안의 파일 전체 목록 (이름, 크기, 수정 시각)
4. 타임라인 정보가 들어있는 파일이 어느 것인지, 그 포맷 (JSON인지, 압축·암호화됐는지)
5. 시간 값의 단위 — 실제 값과 영상 길이를 나눠봐서 판단할 것 (추측 금지)

경로 후보는 검증 대상일 뿐 정답으로 가정하지 마. 후보가 다 빗나가면,
캡컷에서 프로젝트를 하나 저장한 직후 최근 수정된 파일을 역추적해서 찾아.

보고 형식:
- 실제로 실행한 명령과 출력을 그대로 붙여줘
- 경로의 내 사용자명은 <USER>로 치환
- 못 찾은 항목은 "못 찾음"이라고 쓰고 이유를 한 줄
- 파일이 암호화/압축돼 있으면 거기서 멈추고 알려줘.
  그 경우 자동 생성 대신 다른 접근(자막은 SRT 내보내기, 컷은 EDL)을 제안해줘
```

## 2. 자막 구조 뽑기 (diff)

```
자막의 최소 재현 구조를 diff로 뽑아줘.

1. 내가 캡컷에서 할 순서를 알려줘:
   a. 새 프로젝트에 영상 하나만 올리고 저장 → 캡컷 완전 종료 → 폴더 복사 (A)
   b. 자막 "테스트" 하나만 추가하고 저장 → 완전 종료 → 폴더 복사 (B)

2. A와 B의 타임라인 파일을 diff 떠서, 자막 1개 때문에 바뀐 부분만 추출

3. 필드별 주석: 텍스트 본문 / 시작·종료 시각(단위) / 크기·색·폰트·외곽선 /
   화면 위치(좌표계가 절대인지 상대인지 실제 값으로 판단) /
   트랙 세그먼트와 소재(material)를 잇는 id 참조 관계.
   용도 모르는 필드는 "용도 불명"이라고 솔직히 표기

4. templates/subtitle_block.json 으로 저장. 가변값은 {{TEXT}} {{START_US}} {{END_US}}로

5. 검증: 그 템플릿으로 자막 2개짜리 프로젝트를 조립해서 캡컷에서 열리는지 확인.
   안 열리면 뭘 빼먹었는지 다시 diff. 열리는데 자막이 안 보이면 id 참조부터 의심
```

## 3. 내 기본값 조사

```
내 기존 캡컷 프로젝트 전부를 스캔해서 자막 기본값을 데이터로 정해줘.

수집: 폰트 크기(캔버스 높이 대비 비율로도 계산) / 폰트·색·외곽선 /
      화면 세로 위치 / 자막당 글자 수 / 노출 시간 / 해상도 / 만든 날짜

산출:
- 중앙값·최빈값·25~75분위 (평균은 이상치에 흔들리니 참고용으로만)
- 표본 수 명시. 3개 미만이면 "데이터 부족"이라 하고 단정하지 마
- 최근 것일수록 지금 취향에 가깝다. 날짜별 추세가 보이면 알려주고 최근에 가중치를
- 세로(9:16)와 가로(16:9)는 나눠서 집계

출력: config/defaults.yaml (주석에 근거 숫자와 표본 수) + 근거 원본 수치 표
```

## 4. 편집 습관 역분석

```
원본 영상과 내가 편집해 올린 결과 영상을 비교해서 컷 편집 습관을 수치화해줘.

방법:
1. 두 파일의 오디오를 상호상관(cross-correlation)으로 매칭해 편집본의 각 구간이
   원본 어디서 왔는지 찾아줘. 눈대중이나 자막 대조로 때우지 마
2. 매칭 실패 구간은 "정렬 실패"로 표시하고 통계에서 빼줘 (숨기지 말고 보고)

산출:
- 원본/편집본 길이, 삭제 비율(%)
- 삭제된 구간 목록: 시작~끝, 길이, 그 구간 평균 음량
- 삭제 구간 길이 분포 → 내가 몇 초 이상 정적을 자르는지 임계 추정
- ★ 무음인데 살린 구간 목록과 그 이유의 패턴 (화면 변화가 컸나? 맥락인가?)
- 컷 앞뒤로 남긴 여백 중앙값, 컷 개수, 평균 클립 길이

마지막에 이 표를 채워줘. 다음 단계 스크립트의 기본 파라미터로 그대로 쓸 거야:

| 파라미터 | 측정값 | 근거 |
|---|---|---|
| 무음 판정 음량 임계 (dB) | | |
| 무음으로 인정할 최소 길이 (초) | | |
| 컷 앞뒤 남길 여백 (초) | | |
| 삭제 금지할 무음의 화면 변화 임계 | | |
```

## 5. 생성기 만들기

```
영상 파일 하나를 넣으면 캡컷 프로젝트를 만들어주는 CLI를 만들어줘.

  python make_project.py INPUT.mp4 --out "프로젝트명" [옵션]

동작: 음성인식 → 무음 컷 → 자막 얹기 → 캡컷 프로젝트 폴더 생성

필수 조건:
- 원본 영상은 읽기 전용. 절대 수정하지 않는다
- 기본은 --dry-run (계획만 출력, 파일 안 씀). 실제 생성은 --write 필요
- 출력 폴더가 이미 있으면 덮어쓰지 말고 에러
- 하드코딩된 숫자 금지. 전부 config/defaults.yaml에서 읽고 CLI로 덮어쓰기 가능하게
- 단계별 진행 상황 출력
- 중간 산출물(인식 결과, 컷 목록)을 JSON으로 남긴다 — 검사와 디버깅이 여기 의존
- 실패는 조용히 넘기지 말고 종료 코드 1과 원인 출력

만든 다음 실제 영상으로 --dry-run 돌려서 출력을 보여줘.
```

## 6. 검사기

```
생성된 캡컷 프로젝트를 검사하는 스크립트를 만들어줘.

  python verify_project.py "프로젝트폴더"

검사 항목 (각각 통과/실패 + 실패 시 구체적 위치 출력):
1. 필수 파일 존재 + JSON 파싱
2. 참조된 미디어 파일이 실제로 존재
3. 길이 0 이하이거나 서로 겹치는 세그먼트
4. 자막 표시 시각이 영상 길이를 벗어남
5. 빈 자막이나 깨진 글자
6. 자막이 화면 밖으로 나감
7. 총 길이가 예상(원본 − 삭제구간 합)과 ±0.1초 일치
8. 자막이 소재와 트랙 세그먼트 양쪽에 다 연결됨

출력: 사람용 요약 + --json 옵션. 전부 통과 0, 하나라도 실패 1

★ 만들고 나서 먼저 이걸 해줘:
정상 프로젝트를 복사해 8가지를 각각 일부러 깨뜨린 샘플을 만들고,
검사기가 전부 잡아내는지 결과표로 보여줘. 정상본은 통과해야 한다.
```

## 7. 캐시

```
음성 인식 결과를 캐시해서 같은 영상을 다시 돌릴 때 건너뛰게 해줘.

캐시 키 = 아래를 전부 합친 해시:
- 영상 파일의 내용 해시 (파일명·경로 말고 내용. 큰 파일이면 크기 + 앞뒤 바이트
  샘플링도 허용하되 방식을 주석에 명시)
- 음성인식 모델 이름과 버전
- 인식 파라미터 (언어, 모델 크기 등)
→ 하나라도 바뀌면 캐시 미스

- 위치: .cache/transcripts/ (.gitignore에 추가)
- 히트/미스를 로그로 알려줘: "캐시 히트 (2026-07-20 생성)" 처럼
- --no-cache, --clear-cache 옵션
- 캐시 파일에 결과 + 생성 시각 + 키 구성요소를 함께 저장 (추적 가능하게)
- 캐시가 깨져 있으면 조용히 무시하고 재실행 (에러로 죽지 말 것)

검증: 같은 영상 두 번 돌려 2회차 단축을 보여주고,
영상을 조금 수정한 뒤엔 미스가 나는 것도 보여줘.
```

## 8-A. 무음 컷 다듬기

```
무음 처리 규칙을 이렇게 바꿔줘.

1. 무음은 완전 삭제가 아니라 0.5초까지만 줄인다 (config로 조절)
2. 컷 앞뒤로 여백을 남긴다 — 칼같이 자르면 숨소리가 잘려 부자연스럽다
3. 컷 경계는 무음 구간 한가운데로

★ 삭제 금지 규칙 (오디오만으로 판단하지 말 것):
   무음이어도 아래는 원본 길이 유지:
   - 화면 변화량이 큰 구간 (말없이 시연하는 장면)
   - 화면에 텍스트나 UI 변화가 있는 구간
   - --keep 00:01:23-00:01:45 로 직접 지정한 구간
   판정 로그에 구간마다 "삭제/축소/보존"과 이유를 남겨줘.
   내가 로그만 보고 오판을 잡아낼 수 있어야 한다

4. 결과 클립이 최소 길이(기본 1초) 미만이면 앞 클립에 붙인다
```

## 8-B. 자막 줄바꿈

```
자막이 어색하게 잘리는 문제를 고쳐줘. 글자 수만 세지 말고 이 우선순위로:

1순위 — 문장 끝(. ? !)
2순위 — 절 경계(그리고/그런데/근데/하지만/왜냐하면, 쉼표) 앞. 접속어는 다음 줄 첫머리로
3순위 — 어절(띄어쓰기) 경계. 단어 중간 자르기 절대 금지
4순위 — 그래도 길면 최대 글자 수에서. 단 조사/어미만 다음 줄로 넘기지 마
        ("한의원에" → "한의원" / "에" 이런 분리 금지)

제약:
- 한 줄 최대 글자 수·최대 줄 수는 config에서 (3단계 조사값 기본)
- 최소 노출 시간 확보 — 짧게 스쳐 지나가면 못 읽는다
- 읽기 속도 상한(초당 글자 수) 초과 시 쪼개거나 표시 시간을 늘린다
- 자막이 말보다 먼저 뜨면 안 된다. 말이 끝난 뒤 잠깐 더 떠 있는 건 괜찮지만
  다음 자막 시작을 침범하면 안 된다. 이 두 가지를 검사기 항목에 추가
- 나누고 나서 마지막에 "봅니다" 같은 한 어절짜리 자투리가 남으면 안 된다.
  0.3초 스쳐 지나가는 자막이 그렇게 생긴다. 조각 수를 먼저 정하고 균등하게 나눠

바꾼 뒤 실제 영상으로 돌려서 이전/이후 자막 목록을 나란히 보여줘.
```

## 9. 사람 눈 검증

```
지금까지 만든 걸로 성격이 다른 영상 3개를 처리해줘:
말이 계속 이어지는 것 / 무언 시연이 있는 것 / 짧고 컷이 많은 것

각각 체크리스트를 만들어줘. 내가 캡컷에서 열어보고 직접 체크하겠음:
[ ] 오류 없이 열린다
[ ] 영상과 오디오가 어긋나지 않는다
[ ] 자막 타이밍이 말과 맞는다
[ ] 자막 크기·위치가 평소 스타일과 같다
[ ] 잘리면 안 될 구간이 살아있다
[ ] 컷 지점이 어색하지 않다

내가 체크한 결과를 주면, 실패 항목을 검사기의 자동 항목으로 승격시켜줘.
같은 실수가 두 번 나오지 않게.
```

## 10. 회귀 세트

```
앞으로 코드를 고칠 때 예전 기능이 깨지지 않았는지 확인할 회귀 테스트를 만들어줘.

- tests/fixtures/ 에 짧은 샘플 영상 3~5개 (10~30초, 용량 작게)
- 각각의 정답 결과(컷 목록, 자막 목록)를 스냅샷으로 저장
- run_tests.sh 하나로 전부 돌려 스냅샷과 다르면 diff 표시
- 의도적으로 결과를 바꾼 경우 스냅샷 갱신 옵션

이후 어떤 수정을 하든 끝나고 이 테스트 결과를 보여줘.
```
