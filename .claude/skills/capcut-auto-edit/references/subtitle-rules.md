# 한국어 자막 분할 규칙

## 문제

음성인식 결과를 글자 수로만 잘라 자막을 만들면 이런 게 나온다:

```
저희 한의원에서는 다이어트 한약을
처방할 때 체질을 먼저

봅니다
```

읽는 사람이 매 줄마다 걸린다. 한국어는 조사와 어미가 앞말에 붙어야 의미 단위가 유지되는데, 글자 수 기준은 그걸 모른다.

## 분할 우선순위

위에서부터 시도하고, 그 경계로 나눌 수 있으면 아래는 보지 않는다.

**1순위 — 문장 끝.** `.` `?` `!` 뒤에서 나눈다. 가장 자연스럽고 시청자의 호흡과도 맞는다.

**2순위 — 절 경계.** 접속 표현 앞에서 나눈다: `그리고` `그런데` `근데` `하지만` `그래서` `왜냐하면` `또한` `다만` `즉` `예를 들어`. 쉼표 뒤도 여기 해당한다. 접속어는 **다음 줄의 첫머리로** 보낸다 — 앞줄 끝에 남기면 문장이 끊긴 느낌이 든다.

**3순위 — 어절 경계.** 띄어쓰기에서 나눈다. 단어 중간을 자르는 것은 어떤 경우에도 하지 않는다.

**4순위 — 강제 분할.** 그래도 한 어절이 최대 글자 수를 넘으면(긴 합성어, URL 등) 어쩔 수 없이 자른다.

## 조사·어미 고립 금지

3순위로 나눌 때 마지막 조각이 조사나 어미만 남으면 안 된다.

```
나쁨:  "한의원"  /  "에서는 상담을 먼저 합니다"
좋음:  "한의원에서는"  /  "상담을 먼저 합니다"
```

조사만 남는 경우 분할 지점을 한 어절 앞으로 당긴다. 대상 조사·어미: `은` `는` `이` `가` `을` `를` `에` `에서` `에게` `으로` `로` `와` `과` `의` `도` `만` `까지` `부터` `보다` `처럼` `하고` `이다` `입니다` `합니다` `습니다` `했다` `한다`.

## 시간 제약

글자만 잘 나눠도 읽을 시간이 없으면 소용없다.

**최소 노출 시간** — 자막 한 장이 너무 짧게 스쳐 지나가면 못 읽는다. 기본 1.0초. 분할했더니 조각이 이보다 짧아지면 분할하지 말고 합친다.

**읽기 속도 상한 (CPS, 초당 글자 수)** — 한국어는 초당 8~10자가 편안한 상한이다. 이걸 넘으면 둘 중 하나를 한다:
- 자막을 더 잘게 쪼갠다 (발화 구간 안에서 시간을 나눠 배분)
- 표시 시간을 뒤로 늘린다 (단, 다음 자막 시작 시각을 침범하지 않는 선까지만)

**발화 구간 준수** — 자막이 말보다 **먼저 뜨면** 어긋난 느낌이 강하게 든다. 각 조각의 시작은 원래 발화 시작보다 앞설 수 없다. 반대로 말이 끝난 뒤 잠깐 더 떠 있는 것은 자연스럽고 실제로 읽을 시간을 벌어주므로 허용한다 — 단 다음 자막 시작을 침범하면 두 장이 겹쳐 보이므로 거기까지다. 검사기에는 "시작 시각이 발화 시작보다 앞서지 않는가"와 "인접 자막이 겹치지 않는가" 두 항목으로 넣는다.

## 줄 수와 글자 수

- 한 줄 최대 글자 수: 가로 영상 기본 20자, 세로 영상 기본 12자 (3단계 조사값이 있으면 그걸 우선)
- 최대 줄 수: 2줄. 3줄부터는 화면을 가리고 시선이 분산된다.
- 2줄이 될 경우 위아래 길이를 비슷하게 맞춘다. 위가 길고 아래가 한 단어면 균형이 나쁘다.

## 구현

`scripts/split_subtitles.py`가 위 규칙을 구현한다. 규칙을 바꿀 일이 생기면 스크립트 안의 상수(접속어 목록, 조사 목록, 기본 임계값)를 수정하고 `--self-test`로 회귀 확인한다.

입력·출력 형식:

```json
[
  {"start": 1.20, "end": 4.85, "text": "저희 한의원에서는 다이어트 한약을 처방할 때 체질을 먼저 봅니다"}
]
```

출력도 같은 형식이며, 분할된 조각마다 시간이 글자 수 비례로 배분된다.
