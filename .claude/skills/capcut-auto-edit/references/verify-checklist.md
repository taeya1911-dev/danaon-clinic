# 검사기 — 항목과 훼손 테스트

## 왜 검사 항목을 미리 못 박는가

"제대로 됐는지 검사해줘"라고만 하면 파일이 존재하는지 정도만 보는 검사기가 나온다. 그런 검사기는 항상 통과하므로 있으나 마나다. 아래 8항목은 실제로 프로젝트를 망가뜨리는 원인들이고, 각각이 독립적으로 실패할 수 있다.

## 검사 8항목

각 항목은 통과/실패와 **실패 시 구체적 위치**(세그먼트 인덱스, 시각, 필드명)를 출력해야 한다. "실패했습니다"만 나오면 고칠 수가 없다.

| # | 항목 | 판정 기준 |
|---|---|---|
| 1 | 파일 무결성 | 필수 파일이 모두 있고 JSON 파싱이 된다 |
| 2 | 미디어 참조 | 참조된 영상·오디오 파일이 그 경로에 실제로 존재한다 |
| 3 | 세그먼트 정합성 | 길이가 0 이하인 세그먼트가 없고, 같은 트랙 내 세그먼트가 서로 겹치지 않는다 |
| 4 | 자막 시각 범위 | 모든 자막의 표시 구간이 프로젝트 전체 길이 안에 있다 |
| 5 | 자막 내용 | 빈 문자열이나 깨진 글자(mojibake)가 없다 |
| 6 | 자막 화면 위치 | 좌표가 화면 밖으로 나가지 않는다 (좌표계는 1단계에서 확인한 것 기준) |
| 7 | 총 길이 일치 | 프로젝트 총 길이가 (원본 길이 − 삭제 구간 합계)와 ±0.1초 안에서 맞는다 |
| 8 | 자막 연결 | 자막이 소재(material)와 트랙 세그먼트 양쪽에 다 등록돼 있고 id가 서로 가리킨다 |

7번은 컷 계산 오류를 잡는 항목이라 중요하다. 삭제 구간을 두 번 빼거나 겹치는 구간을 중복 계산하면 여기서 걸린다.

8번은 "열리는데 자막이 안 보이는" 증상의 원인을 직접 잡는다.

## 출력 규약

- 사람이 읽는 요약을 기본으로, `--json` 옵션으로 기계가 읽는 형식도 낸다 (회귀 테스트에서 쓴다)
- 전부 통과하면 종료 코드 0, 하나라도 실패하면 1

## 훼손 테스트 — 만든 직후 반드시

검사기를 만들었으면 **그 검사기가 실제로 실패할 수 있는지**를 먼저 증명한다. 이 확인 없이는 검사기가 도는지 아닌지 알 방법이 없고, 조용히 통과만 하는 검사기를 믿고 있는 게 가장 위험한 상태다.

정상 프로젝트를 복사해 아래 8가지를 각각 하나씩 적용한 샘플을 만든다:

1. 필수 파일 하나 삭제 (또는 JSON 중괄호 하나 깨뜨리기)
2. 미디어 경로를 존재하지 않는 파일로 변경
3. 세그먼트 하나의 종료 시각을 시작보다 앞으로
4. 자막 하나의 시작 시각을 영상 길이보다 뒤로
5. 자막 텍스트를 빈 문자열로
6. 자막 위치 좌표를 화면 밖 값으로
7. 세그먼트 하나의 길이를 임의로 늘려 총 길이 어긋나게
8. 자막 세그먼트의 소재 id를 없는 값으로

**기대 결과:** 8개 샘플 각각에서 해당 항목이 실패하고, 정상본은 8항목 전부 통과. 결과를 표로 사용자에게 보인다.

한 샘플에서 여러 항목이 같이 실패하는 건 괜찮다(예: 3번 훼손이 7번도 건드림). 문제는 **어떤 샘플에서도 실패하지 않는 항목**이 있는 경우인데, 그건 그 검사 항목이 실질적으로 아무것도 안 보고 있다는 뜻이다.

## 항목 늘리기

9단계(사람 눈 검증)에서 사용자가 지적한 문제는 여기 항목으로 추가한다. 사람이 두 번 잡아낸 문제는 검사기가 잡아야 한다.
