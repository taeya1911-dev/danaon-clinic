# 캡컷 프로젝트 포맷 — 확인 절차

여기 적힌 경로와 구조는 **검증 대상 후보**다. 정답으로 가정하고 코드를 쓰면 안 된다.
캡컷은 자동 업데이트로 스키마를 바꾸고, 지역판/설치 방식(공식 설치, 스토어 앱)마다 경로가 다르다.

## 1. 설치 버전 확인

버전을 먼저 알아야 나중에 "어제 되던 게 안 되는" 상황에서 원인을 짚을 수 있다. `state.json`에 기록한다.

- Windows: 설치 폴더의 실행 파일 속성, 또는 앱 내 설정 화면
- macOS: `.app` 번들의 `Info.plist`에서 `CFBundleShortVersionString`

## 2. 프로젝트 폴더 찾기

확인해볼 후보:

| OS | 후보 경로 |
|---|---|
| Windows | `%LOCALAPPDATA%\CapCut\User Data\Projects\` |
| Windows (스토어판) | `%LOCALAPPDATA%\Packages\` 하위 |
| macOS | `~/Movies/CapCut/User Data/Projects/` |
| macOS (대체) | `~/Library/Containers/` 하위 |

후보가 다 빗나가면 추측을 늘리지 말고 **최근 수정된 파일로 역추적한다.** 캡컷에서 프로젝트를 하나 저장하게 한 뒤, 그 직후 몇 분 안에 수정된 파일을 사용자 홈 아래에서 찾으면 위치가 바로 드러난다. 이 방법은 경로 지식 없이도 어떤 버전에서든 통한다.

한국어판 폴더명이 다를 수 있으므로 이름 매칭보다 수정 시각 기준 탐색이 안전하다.

## 3. 타임라인 파일 식별

프로젝트 폴더 안 파일들을 크기순으로 보면 타임라인 데이터가 가장 크다. 텍스트로 열어 다음을 확인한다:

- JSON으로 파싱되는가 (안 되면 압축·암호화 → 여기서 중단하고 대안 제안)
- 트랙/세그먼트/소재에 해당하는 구조가 보이는가
- 사용자가 넣은 자막 문자열을 파일에서 검색하면 나오는가 ← 이게 가장 확실한 식별법

`draft_content.json`, `draft_meta_info.json` 같은 이름이 흔하지만 이름에 의존하지 말고 내용으로 판단한다.

## 4. 시간 단위 판정 (추측 금지)

시간 단위를 틀리면 자막이 1000배 어긋난다. 다음처럼 실측한다:

1. 영상의 실제 길이를 초 단위로 구한다 (`ffprobe`)
2. 타임라인에서 전체 길이에 해당하는 값을 찾는다
3. 나눠본다 — 비율이 1이면 초, 1,000이면 밀리초, 1,000,000이면 마이크로초

캡컷은 마이크로초를 쓰는 경우가 많지만, **반드시 위 계산으로 확인하고** 결과를 `state.json`의 `time_unit`에 기록한다.

## 5. 자막 구조 추출 — diff 절차

자막 하나에 관여하는 필드는 파일 여기저기 흩어져 있다. 전체를 읽어서 추론하려 들면 어느 필드가 자막용인지 특정할 수 없고, 결국 추측이 섞인다. 두 상태의 차이만 보면 정답이 그냥 드러난다.

**사용자에게 안내할 절차:**

1. 캡컷에서 새 프로젝트를 만들고 영상 하나만 올린 뒤 저장
2. **캡컷을 완전히 종료** (종료해야 파일에 반영된다)
3. 프로젝트 폴더를 통째로 복사 → `A`
4. 캡컷을 다시 열어 자막 "테스트" 하나만 추가하고 저장
5. **다시 완전히 종료**
6. 폴더를 복사 → `B`

**diff에서 읽어낼 것:**

- 자막 텍스트 본문이 들어가는 위치
- 시작/종료 시각 필드와 단위
- 글자 크기, 색상, 폰트, 외곽선/그림자
- 화면상 위치 — 좌표계가 절대 픽셀인지 상대값(-1~1 등)인지는 실제 값의 범위를 보고 판단
- **소재(material)와 트랙 세그먼트를 잇는 id 참조 관계** ← 여기가 자주 누락된다
- 용도를 모르겠는 필드는 "용도 불명"으로 표기하고 템플릿에는 원본값 그대로 남긴다

**검증 방법:** 추출한 템플릿으로 자막 2개짜리 프로젝트를 조립해 캡컷에서 연다. 열리는데 자막이 안 보이면 id 참조를 먼저 의심한다. 파일 자체가 안 열리면 필수 필드를 빼먹은 것이므로 diff를 다시 본다.

**개인정보:** 추출 결과에 사용자명이 포함된 경로가 들어가므로 `<USER>`로 치환해 저장한다.

## 6. 안전 수칙

- 캡컷 실행 중에는 프로젝트 파일을 쓰지 않는다. 앱이 종료 시 메모리 내용으로 덮어써서 작업이 날아간다.
- 실험은 항상 복사본에서 한다. 원본 프로젝트는 건드리지 않는다.
- 새 프로젝트를 만들 때 기존 폴더명을 재사용하지 않는다.
