## 이미 만들어져 있고 검증된 것

**`.claude/skills/capcut-auto-edit/scripts/silence_plan.py`**
무음 감지 + 장면 변화 감지를 겹쳐 구간별 "삭제/축소/보존"을 정한다.
실제 영상으로 전체 경로 검증 완료 — 설계한 무음 구조를 20ms 오차로 감지했고,
화면 변화가 있는 무음(= 말없이 시연하는 구간)은 보존했다. 자체 테스트 20개 통과.

**`.claude/skills/capcut-auto-edit/scripts/split_subtitles.py`**
한국어 자막을 문장 > 절 > 어절 순으로 나눈다. 조사 고립과 자투리 자막을 막는다.
자체 테스트 14개 통과.

둘 다 `--self-test`로 언제든 회귀 확인 가능. 재개하면 먼저 한 번 돌려보고 시작한다.

## 다음에 할 일

캡컷이 설치된 컴퓨터에서 Claude Code를 열고 이 저장소에서:

```
캡컷 자동화 1단계부터 시작하자
```

스킬이 로드되면서 1단계(포맷 탐색)부터 진행된다.
1단계에서 알아낸 캡컷 버전·경로·시간 단위는 `.capcut-auto/state.json`에 기록된다
(이 파일은 사용자명이 포함된 로컬 경로를 담으므로 git에 올리지 않는다).

## 원격 세션에서 안 되는 것

다음은 클라우드 컨테이너의 제약이라 사용자 컴퓨터에서 해야 한다.

- **캡컷이 없다** → 1·2단계 불가, 생성 결과를 열어서 확인 불가
- **음성인식 모델 다운로드가 막혀 있다** → 자막 텍스트를 직접 넘겨야 함
- 컨테이너는 비활성 후 회수된다 → 올린 파일은 남지 않는다

원격에서도 되는 것: ffmpeg 설치(`pip install imageio-ffmpeg`), 무음·장면 감지,
컷 계획 생성, 대본을 텍스트로 주면 자막 타이밍 계산.

## 결정해둔 것 (다시 논의하지 말 것)

- **순서를 지킨다.** 1·2단계를 건너뛰고 5단계로 가면 "파일은 만들어졌는데 캡컷에서
  안 열림"으로 끝나고, 그때는 원인 추적이 훨씬 비싸다.
- **무음 판정은 오디오만으로 하지 않는다.** 화면 변화를 같이 본다. 말없이 시연하는
  구간이 날아가는 게 사용자가 가장 싫어하는 실패다.
- **자막 시간 규칙:** 말보다 먼저 뜨면 안 된다. 말이 끝난 뒤 잠깐 더 떠 있는 건 괜찮다.
  다음 자막 시작은 침범하지 않는다.
- **검사기는 만들자마자 일부러 깨뜨려본다.** 항상 통과하는 검사기는 없느니만 못하다.
