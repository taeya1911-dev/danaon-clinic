# 영상 자동화 편집 프롬프트 (개정판)

캡컷(CapCut) 프로젝트를 자동 생성하는 도구를 AI와 함께 만들 때 쓰는 단계별 프롬프트입니다.
원본 8단계의 순서는 그대로 유지하고, **각 단계에 "완료 기준"과 "다음 단계로 넘기는 값"을 추가**했습니다.

---

## 개정 요약 — 원본에서 뭘 고쳤나

| # | 원본 | 문제 | 개정 |
|---|------|------|------|
| 1 | "어디에 저장하는지 찾아줘" | 실제로 안 찾아보고 블로그에서 본 경로를 답해도 구분 불가 | **증거 강제**: 실제 파일 목록 + 캡컷 버전 + 수정 시각. 못 찾으면 "모름"이라고 답하게 |
| 2 | "구조 그대로 뽑아줘" | 자막 필드가 수백 개 중 어느 것인지 특정 불가 | **diff 기법**: 자막 없는 프로젝트 → 자막 1개 추가 → 두 파일 diff. 바뀐 필드만이 정답 |
| 3 | "보통 얼마인지" | 평균값은 이상치에 무너지고, 해상도 다르면 비교 자체가 무의미 | **중앙값 + 해상도 정규화 + 표본 수 명시**, 결과는 산문이 아니라 `config` 파일로 |
| 4 | "숫자로 분석해줘" | 분석해놓고 5단계에 안 씀 | **4단계 출력 = 5단계 입력**으로 명시. 정렬 방법(오디오 상관관계)까지 지정 |
| 5 | "스크립트 만들어줘" | 원본 덮어쓰기·되돌리기 불가 위험 | **원본 읽기 전용 + dry-run 필수 + 파라미터 전부 CLI 노출** |
| 6 | "검사하는 스크립트" | "제대로"가 정의 안 됨. 항상 통과하는 검사기가 나옴 | **검사 항목 7개 명시 + 일부러 깨뜨려서 검사기가 실패하는지 먼저 확인** |
| 7 | "저장해뒀다 건너뛰게" | 파일명 기준 캐시는 파일이 바뀌어도 옛 결과를 씀 | **내용 해시 + 모델·파라미터 버전**을 키로. 무효화 규칙 명시 |
| 8 | "0.5초로 / 문맥 보고 나눠줘" | 무음 삭제가 무언 시연 구간을 날림 | **보호 구간 규칙을 1급 요구사항으로 승격**(오디오 + 화면 변화량 동시 판정) |
| + | — | 백업·회귀 테스트·사람 눈 검증이 없음 | **0단계(안전장치), 9단계(캡컷에서 실제로 열기)** 추가 |

## 0단계 — 공통 규칙 (먼저 한 번만, `CLAUDE.md`에 넣어두면 매번 안 써도 됨)

```
이 프로젝트 작업 시 항상 지킬 규칙:

[사실 확인]
- 파일 경로, 스키마 필드명, 버전 번호는 반드시 실제로 열어보고 확인한 것만 말해.
- 확인 못 한 건 "확인 못 함"이라고 명시해. 그럴듯한 추측을 사실처럼 쓰지 마.
- 캡컷은 버전마다 프로젝트 포맷이 바뀐다. 내 설치 버전을 먼저 확인하고,
  인터넷에서 본 구조와 다르면 내 파일 쪽을 정답으로 삼아.

[안전]
- 원본 영상 파일과 기존 캡컷 프로젝트는 절대 수정·삭제하지 마. 읽기 전용.
- 새 프로젝트는 항상 새 폴더에 만들어. 기존 폴더 이름 재사용 금지.
- 파괴적 동작(덮어쓰기, 삭제)은 실행 전에 나한테 물어봐.
- 캡컷을 켜둔 상태로 프로젝트 파일을 건드리면 앱이 덮어써서 날아간다.
  파일 쓰기 전에 캡컷이 실행 중인지 확인하고, 켜져 있으면 먼저 알려줘.

[작업 방식]
- 한 번에 한 단계만. 끝나면 검증 결과를 보여주고 멈춰.
- 코드를 만들면 반드시 실제로 실행해서 통과하는 걸 보여줘. "될 겁니다"는 안 됨.
- 개인정보(내 이름, 계정 ID, 파일 경로 속 사용자명)는 결과물에 남기지 말고
  <USER> 같은 placeholder로 치환해.
```

## 1단계 — 탐색

> 원본: *"캡컷이 프로젝트 파일을 어디에 어떤 형식으로 저장하는지 찾아줘"*

**왜 이 순서인가:** 저장 위치와 포맷을 모르면 그 뒤 전부가 추측 위에 쌓인다.

```
캡컷 데스크톱이 프로젝트를 어디에 어떤 형식으로 저장하는지 내 컴퓨터에서 직접 확인해줘.

찾을 것:
1. 내 캡컷 버전 (앱 정보 또는 설치 폴더에서)
2. 프로젝트가 저장되는 실제 폴더 경로
3. 프로젝트 폴더 하나 안에 있는 파일 전체 목록 (이름, 크기, 수정 시각)
4. 그중 타임라인 정보가 들어있는 파일이 어느 것인지, 그리고 그 포맷
   (JSON인지, 압축·암호화됐는지)
5. 시간 값의 단위 (초/밀리초/마이크로초) — 실제 값과 영상 길이를 대조해서 판단

확인 후보 (검증 대상일 뿐, 정답으로 가정하지 말 것):
- Windows: %LOCALAPPDATA%\CapCut\User Data\Projects\
- macOS: ~/Movies/CapCut/User Data/Projects/
- 한국어판 설치명이 다를 수 있으니 실제 검색으로 확인

보고 형식:
- 실제로 실행한 명령과 그 출력을 그대로 붙여줘
- 경로는 내 사용자명을 <USER>로 치환
- 못 찾은 항목은 "못 찾음"이라고 쓰고, 왜 못 찾았는지 한 줄
- 파일이 JSON이 아니라 암호화/압축돼 있으면 거기서 멈추고 알려줘.
  그 경우 자동 생성 대신 다른 접근(예: 캡컷 대신 편집 결과를 EDL/SRT로 내보내기)을 제안해줘
```

**완료 기준:** 프로젝트 폴더 안 파일 목록이 실제 출력으로 나왔고, 타임라인 파일을 열어서 사람이 읽을 수 있음을 보여줬다.
**흔한 실패:** 인터넷에서 본 경로를 그대로 답함 → 버전이 다르면 필드명이 안 맞아 5단계에서 무너진다.

## 2단계 — 정답 뽑기 (상상 금지, 기존 것에서 복사)

> 원본: *"자막이 들어있는 내 기존 캡컷 프로젝트를 찾아서 자막 설정 구조를 그대로 뽑아줘"*

**핵심 보완 — diff로 뽑기.** 자막 하나 넣는 데 관여하는 필드는 파일 전체에 흩어져 있다. 통째로 읽으면 뭐가 자막용인지 특정을 못 한다. **자막 없는 상태와 자막 1개 있는 상태를 만들어 diff를 뜨면** 바뀐 부분이 곧 정답이다.

```
자막의 최소 재현 구조를 diff로 뽑아줘.

절차:
1. 내가 캡컷에서 직접 하겠음 — 네가 순서를 알려줘:
   a. 새 프로젝트 만들고 영상 하나만 올린 뒤 저장 → 이 폴더를 A로 복사
   b. 같은 프로젝트에 자막 "테스트" 딱 하나 추가하고 저장 → 이 폴더를 B로 복사
   (캡컷을 완전히 종료한 뒤 복사해야 저장이 반영된다)

2. A와 B의 타임라인 파일을 diff 떠서, 자막 1개 때문에 늘어난/바뀐 부분만 추출해줘

3. 추출한 구조에 필드별 주석을 달아줘:
   - 자막 텍스트 본문이 들어가는 곳
   - 시작/종료 시각 (단위 포함)
   - 글자 크기, 색상, 폰트, 외곽선/그림자
   - 화면상 위치 (좌표계가 절대인지 상대(-1~1 등)인지 실제 값으로 판단)
   - 트랙/세그먼트와 소재(material)를 연결하는 id 참조 관계
   - 용도를 모르겠는 필드는 "용도 불명"이라고 솔직히 표기

4. 결과를 templates/subtitle_block.json 으로 저장.
   가변값은 {{TEXT}}, {{START_US}}, {{END_US}} 같은 placeholder로 바꿔줘

5. 검증: 그 템플릿으로 자막 2개짜리 프로젝트를 손으로 조립해서
   캡컷에서 열리는지 내가 확인할 수 있게 해줘. 안 열리면 뭘 빼먹은 건지 다시 diff
```

**완료 기준:** 템플릿으로 조립한 프로젝트가 캡컷에서 실제로 열리고 자막이 보인다.
**흔한 실패:** id 참조(세그먼트↔소재 연결)를 빼먹음 → 파일은 열리는데 자막이 안 보인다.

## 3단계 — 내 습관 파악 (기본값을 데이터로)

> 원본: *"내 기존 프로젝트들 자막 크기가 보통 얼마인지 조사해서 기본값 정해줘"*

**핵심 보완:** 평균 대신 **중앙값**, 그리고 **해상도 정규화**. 1080p 프로젝트와 4K 프로젝트의 폰트 크기 숫자는 그대로 비교하면 안 된다.

```
내 기존 캡컷 프로젝트 전부를 스캔해서 자막 기본값을 데이터로 정해줘.

수집할 항목 (프로젝트별, 자막별):
- 폰트 크기 — 캔버스 높이 대비 비율로도 함께 계산
- 폰트 종류, 색상, 외곽선/배경 유무
- 화면상 세로 위치
- 자막 1개당 글자 수, 화면에 떠 있는 시간
- 프로젝트 해상도, 만든 날짜

산출:
- 항목별 중앙값 / 최빈값 / 25~75분위 범위 (평균은 이상치에 흔들리니 참고용으로만)
- 표본 수를 반드시 명시. 프로젝트 3개 미만이면 "데이터 부족"이라고 말하고
  기본값을 단정하지 마
- 최근 프로젝트일수록 지금 취향에 가깝다. 날짜별 추세가 보이면 알려주고,
  기본값은 최근 것에 가중치를 둬
- 세로 영상(9:16)과 가로 영상(16:9)은 나눠서 집계

출력:
- config/defaults.yaml 파일로 저장 (주석에 근거 숫자와 표본 수 기록)
- 근거가 된 원본 수치 표도 함께 보여줘
```

**완료 기준:** `defaults.yaml`이 생겼고, 각 값 옆에 "표본 N개, 중앙값" 근거가 붙어 있다.

## 4단계 — 목표 측정 (내가 실제로 뭘 잘라냈나)

> 원본: *"이 유튜브 영상이 내가 같은 원본으로 편집한 거야. 원본이랑 비교해서 내가 뭘 잘라냈는지 숫자로 분석해줘"*

**핵심 보완 두 가지.** ① 두 영상을 어떻게 정렬할지 방법을 지정해야 한다(눈대중 금지 → 오디오 파형 상관관계). ② **이 단계의 출력이 5단계의 기본 파라미터가 된다**는 걸 명시해야 측정이 감상으로 끝나지 않는다.

```
원본 영상과 내가 편집해서 올린 결과 영상을 비교해서, 내 컷 편집 습관을 수치화해줘.

방법:
1. 두 파일의 오디오를 추출하고, 상호상관(cross-correlation)으로 편집본의 각 구간이
   원본의 어느 구간에서 왔는지 매칭해줘. 눈대중이나 자막 대조로 때우지 말 것
2. 매칭 실패 구간이 있으면 "정렬 실패"로 따로 표시하고 통계에서 빼줘 (숨기지 말고 보고)

산출 (숫자로):
- 원본 길이 / 편집본 길이 / 삭제 비율(%)
- 삭제된 구간 목록: 시작~끝, 길이, 그 구간의 평균 음량
- 삭제 구간의 길이 분포 → 내가 몇 초 이상 되는 정적을 잘라내는지 (임계 추정)
- 남긴 구간 중 "무음이지만 살린" 것들의 목록 ← 이게 제일 중요.
  여기서 왜 살렸는지 패턴을 찾아줘 (화면 변화가 컸나? 앞뒤 발화의 맥락인가?)
- 컷 사이에 남긴 여백(발화 시작 전/후로 몇 초 남겼는지) 중앙값
- 컷 개수, 평균 클립 길이

마지막에 이 표를 채워줘 — 이건 다음 단계 스크립트의 기본 파라미터로 그대로 쓸 거야:

| 파라미터 | 측정값 | 근거 |
|---|---|---|
| 무음 판정 음량 임계 (dB) | | |
| 무음으로 인정할 최소 길이 (초) | | |
| 컷 앞뒤 남길 여백 (초) | | |
| 삭제 금지할 무음의 화면 변화 임계 | | |
```

**완료 기준:** 파라미터 표 4칸이 실측치로 채워졌다.
**연결:** 이 표 → 5단계 `config/defaults.yaml`의 컷 편집 섹션.

## 5단계 — 만들기

> 원본: *"영상 파일 하나 넣으면 무음 자르고 자막 넣은 캡컷 프로젝트 만들어주는 스크립트 만들어줘"*

```
영상 파일 하나를 넣으면 캡컷 프로젝트를 만들어주는 CLI 스크립트를 만들어줘.

사용법:
  python make_project.py INPUT.mp4 --out "프로젝트명" [옵션]

동작:
1. 음성 인식으로 발화 구간과 자막 텍스트를 뽑는다
2. 무음 구간을 잘라낸다 (4단계에서 측정한 값이 기본값)
3. 2단계 템플릿으로 자막을 얹는다 (3단계에서 측정한 크기/위치가 기본값)
4. 캡컷 프로젝트 폴더를 새로 만들어 저장한다

필수 조건:
- 원본 영상은 절대 수정하지 않는다. 읽기 전용으로만 연다
- 기본은 --dry-run: 뭘 자르고 자막을 몇 개 넣을지 계획만 출력하고 파일은 안 쓴다.
  실제 생성은 --write 를 줘야 한다
- 출력 폴더가 이미 있으면 덮어쓰지 말고 에러
- 하드코딩된 숫자 금지. 모든 임계값은 config/defaults.yaml에서 읽고 CLI로 덮어쓸 수 있게
- 진행 상황을 단계별로 출력 (음성인식 중 / 무음 분석 중 / 프로젝트 쓰는 중)
- 중간 산출물(인식 결과, 컷 목록)을 JSON으로도 남긴다 — 나중에 디버깅과 검사에 쓴다
- 실패는 조용히 넘어가지 말고 종료 코드 1과 함께 원인을 출력

만든 다음 실제 영상 하나로 --dry-run 을 돌려서 출력을 보여줘.
```

**완료 기준:** `--dry-run` 출력이 실제 영상에 대해 나왔고, 컷 개수·자막 개수가 상식적이다.

## 6단계 — 검사기 (만들자마자 바로)

> 원본: *"만들어진 프로젝트가 제대로 됐는지 검사하는 스크립트도 만들어줘"*

**핵심 보완:** "제대로"를 항목으로 못 박고, **검사기가 실제로 실패할 수 있는지 먼저 증명**한다. 항상 통과하는 검사기는 없는 것만 못하다.

```
생성된 캡컷 프로젝트를 검사하는 스크립트를 만들어줘.

  python verify_project.py "프로젝트폴더"

검사 항목 (각각 통과/실패와 실패 시 구체적 위치를 출력):
1. 필수 파일이 다 있고 JSON 파싱이 되는가
2. 참조된 미디어 파일이 실제로 그 경로에 존재하는가
3. 타임라인 세그먼트 중 길이가 0 이하이거나 서로 겹치는 게 있는가
4. 자막의 표시 시각이 영상 전체 길이를 벗어나지 않는가
5. 자막 텍스트가 비어있거나 깨진 글자(mojibake)가 있는가
6. 자막 위치가 화면 밖으로 나가는가
7. 프로젝트 총 길이가 예상 길이(원본 - 삭제구간 합계)와 일치하는가 (±0.1초)
8. 자막이 소재(material)와 트랙 세그먼트 양쪽에 다 연결돼 있는가

출력:
- 사람이 읽는 요약 + --json 옵션으로 기계가 읽는 형식
- 전부 통과하면 종료 코드 0, 하나라도 실패하면 1

중요 — 만들고 나서 이걸 먼저 해줘:
정상 프로젝트를 복사해서 일부러 8가지를 각각 깨뜨린 샘플을 만들고,
검사기가 그 8개를 전부 잡아내는지 보여줘.
정상본은 통과하고 깨진 것들은 실패해야 한다. 이 결과표를 보여준 다음에 넘어가.
```

**완료 기준:** 깨뜨린 샘플 8개 전부에서 검사기가 실패를 냈고, 정상본은 통과했다.

## 7단계 — 빠르게 (반복 테스트 가능하게)

> 원본: *"음성인식 결과를 저장해뒀다가 같은 영상 다시 돌릴 땐 건너뛰게 해줘"*

**핵심 보완:** 캐시 키를 **파일명이 아니라 내용 해시**로. 파일명이 같은데 내용이 바뀌면 옛 결과를 써서 디버깅이 지옥이 된다.

```
음성 인식 결과를 캐시해서 같은 영상을 다시 돌릴 때 건너뛰게 해줘.

캐시 키 = 아래를 전부 합친 해시:
- 영상 파일의 내용 해시 (파일명·경로 말고 내용. 큰 파일이면 크기 + 앞뒤 일부 바이트 샘플링도 허용하되 그 방식을 주석에 명시)
- 음성인식 모델 이름과 버전
- 인식 관련 파라미터 (언어, 모델 크기 등)
→ 이 중 하나라도 바뀌면 캐시 미스가 나야 한다

동작:
- 캐시 위치: .cache/transcripts/ (git에 올라가지 않게 .gitignore에 추가)
- 히트/미스를 로그로 알려줘: "캐시 히트 (2026-07-20 생성)" 처럼
- --no-cache 로 강제 재실행, --clear-cache 로 비우기
- 캐시 파일에는 인식 결과 + 생성 시각 + 위 키 구성요소를 함께 저장
  (나중에 왜 이 결과가 나왔는지 추적 가능하게)
- 캐시 파일이 깨져 있으면 조용히 무시하고 재실행 (에러로 죽지 말 것)

검증: 같은 영상을 두 번 돌려서 2회차 소요 시간이 확 줄어드는 걸 보여주고,
영상 파일을 조금 수정한 뒤 돌리면 캐시 미스가 나는 것도 보여줘.
```

**완료 기준:** 2회차 실행 시간 단축이 실측으로 나왔고, 내용이 바뀐 파일에서 미스가 나는 걸 확인했다.

## 8단계 — 다듬기 (컷 편집)

> 원본: *"무음을 0.5초까지 줄여줘 / 자막이 어색하게 잘려, 문맥 보고 나눠줘"*
> *"(ex. 말없이 시연하는 구간은 삭제 금지)"*

괄호 안 예외가 사실 제일 중요한 요구사항입니다. 별도 규칙으로 승격시켰습니다.

### 8-A. 무음 컷

```
무음 처리 규칙을 이렇게 바꿔줘.

1. 무음 구간은 완전 삭제가 아니라 0.5초까지만 줄인다 (config로 조절 가능)
2. 컷 지점 앞뒤로 여백을 남긴다 — 말 시작 직전, 끝난 직후를 칼같이 자르면
   숨소리가 잘려서 부자연스럽다 (4단계에서 측정한 여백값 사용)
3. 컷 경계는 무음 구간의 한가운데로 잡는다

★ 삭제 금지 규칙 (오디오만으로 판단하지 말 것):
   무음이어도 아래에 해당하면 원본 길이 그대로 유지한다.
   - 화면 변화량이 큰 구간 (프레임 간 차이가 임계 이상) — 말없이 시연하는 장면
   - 화면에 텍스트나 UI 변화가 있는 구간
   - 사용자가 --keep 00:01:23-00:01:45 로 직접 지정한 구간
   판정 로그에 각 무음 구간마다 "삭제 / 축소 / 보존"과 그 이유를 남겨줘.
   내가 로그만 보고 오판을 잡아낼 수 있어야 한다

4. 컷을 너무 잘게 내지 마라. 결과 클립이 최소 길이(기본 1초) 미만이면
   앞 클립에 붙인다
```

### 8-B. 자막 줄바꿈

```
자막이 어색하게 잘리는 문제를 고쳐줘. 글자 수만 세서 자르지 말고 이 우선순위로:

1순위 — 문장 끝(. ? !)에서 나눈다
2순위 — 절 경계(그리고/그런데/근데/하지만/왜냐하면, 쉼표) 앞에서 나눈다
3순위 — 어절(띄어쓰기) 경계. 단어 중간에서 자르는 건 절대 금지
4순위 — 그래도 길면 최대 글자 수에서 자르되, 조사/어미만 다음 줄로 넘기지 않는다
        ("한의원에" → "한의원" / "에" 이런 분리 금지)

제약:
- 한 줄 최대 글자 수, 최대 줄 수는 config에서 (3단계 조사값을 기본으로)
- 한 자막의 최소 노출 시간 확보 — 너무 짧게 스쳐 지나가면 못 읽는다
- 읽기 속도 상한(초당 글자 수)을 넘으면 자막을 쪼개거나 표시 시간을 늘린다
- 자막 표시 구간은 실제 발화 구간과 어긋나면 안 된다.
  나눈 뒤에도 각 조각의 시작·종료가 원래 발화 타이밍 안에 들어가는지 검사기에 항목 추가

바꾼 뒤 실제 영상으로 돌려서 이전/이후 자막 목록을 나란히 보여줘.
```

**완료 기준:** 무음 판정 로그에 구간별 사유가 남고, 무언 시연 구간이 "보존"으로 찍혔다.

## 9단계 — 사람 눈 검증 (원본에 없던 단계, 반드시 필요)

검사기가 통과해도 캡컷에서 안 열리거나 이상하게 보일 수 있습니다. 자동 검사는 파일 구조만 보지 화면은 못 봅니다.

```
지금까지 만든 걸로 실제 영상 3개를 처리해줘. 서로 성격이 다른 걸로 고를 것:
- 말이 계속 이어지는 영상
- 무언 시연 구간이 있는 영상
- 짧고 컷이 많은 영상

각각에 대해 체크리스트를 만들어줘. 내가 캡컷에서 열어보고 직접 체크하겠음:
[ ] 프로젝트가 오류 없이 열린다
[ ] 영상과 오디오가 어긋나지 않는다
[ ] 자막 타이밍이 말과 맞는다
[ ] 자막 크기·위치가 내 평소 스타일과 같다
[ ] 잘리면 안 될 구간이 살아있다
[ ] 컷 지점이 어색하지 않다

내가 체크한 결과를 주면, 실패 항목을 검사기(6단계)의 자동 검사 항목으로 승격시켜줘.
같은 실수가 두 번 나오지 않게.
```

## 10단계 — 회귀 세트 (계속 쓸 거라면)

```
앞으로 코드를 고칠 때마다 예전 기능이 깨지지 않았는지 확인할 회귀 테스트를 만들어줘.

- tests/fixtures/ 에 짧은 샘플 영상 3~5개 (10~30초, 용량 작게)
- 각각의 "정답" 결과(컷 목록, 자막 목록)를 스냅샷으로 저장
- run_tests.sh 하나로 전부 돌려서 스냅샷과 다르면 diff를 보여주게
- 의도적으로 결과를 바꾼 경우엔 스냅샷을 갱신하는 옵션도

이걸 만든 뒤엔, 앞으로 어떤 수정을 하든 끝나고 이 테스트를 돌린 결과를 보여줘.
```

```yaml
# 3단계(기존 프로젝트 조사)에서 채움

  outline:
  position_y:           # 화면 하단 기준 상대 위치
  max_chars_per_line:
  max_lines:
  min_duration_sec:     # 최소 노출 시간
  max_cps:              # 초당 읽기 글자 수 상한

# 4단계(내 편집본 역분석)에서 채움
cut:
  silence_threshold_db:
  min_silence_sec:      # 이보다 짧은 정적은 건드리지 않음
  keep_silence_sec: 0.5 # 무음을 여기까지만 줄임

  pad_after_sec:

  language: ko
  cache_dir: .cache/transcripts
```
